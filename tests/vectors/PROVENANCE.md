# Test vector provenance (sd_crypto)

Everything under `tests/vectors/` is test **data**, never code (decisions.md D1, 01 §2.5). It is read
at run time by `sd-test-crypto` (`tests/unit/sd_crypto`).

## `openssh/`

- `ed25519_aes256ctr_r16.key` (+ `.pub`): generated on 2026-10-24 with
  `ssh-keygen -t ed25519 -a 16 -N "correct horse battery staple" -C "sd_crypto test fixture"`
  (OpenSSH_for_Windows_9.5p2). Used as an end-to-end vector for bcrypt_pbkdf + aes256-ctr + Ed25519
  key derivation. The passphrase is part of the fixture, not a secret.

## `refimpl/`

- `x25519_random.txt`: 500 random X25519 cases (including non-canonical u >= p and inputs with
  bit 255 set) produced by `refimpl/x25519_ref.py`, our own deliberately simple big-integer
  implementation of RFC 7748 §5 (independent arithmetic cross-check, 01 §2.7.4). Regenerate with
  `python -I tests/vectors/refimpl/x25519_ref.py tests/vectors/refimpl/x25519_random.txt`.

## Vectors embedded in the test sources

- FIPS 180-4 / NIST CSRC examples (SHA-256/384/512), RFC 4231 (HMAC-SHA-256/384/512), RFC 7914 §11
  (PBKDF2-HMAC-SHA-256), FIPS 197 Appendix C (AES), NIST SP 800-38A F.2/F.5 (CBC, CTR), the GCM
  specification test cases (McGrew-Viega, used by SP 800-38D validation), RFC 7748 §5.2 and §6.1
  (X25519), RFC 8032 §7.1 (Ed25519), RFC 8439 §2.3.2, §2.5.2 (ChaCha20 block, Poly1305).
- bcrypt_pbkdf: the three vectors published with Go's
  `golang.org/x/crypto/ssh/internal/bcrypt_pbkdf` tests, stated there to be generated by the OpenBSD
  reference implementation (numbers only; no code taken).

## `pq/`: M2 symmetric / post-quantum vectors (ML-KEM, SHA-3, BLAKE2b/Argon2, AES-CBC, TDES); see `pq/PROVENANCE.md`.

  Not used, with the reason: the DER-encoded `ecdsa_*_test.json` (SSH carries r and s as mpints, so the P1363
  files cover the same arithmetic cases), the ASN.1 `ecdh_*_test.json` / `_pem` / `_webcrypto` variants (SPKI
  parsing is not sd_crypto's job; `_ecpoint` has the same cases), `rsa_pkcs1_*_test.json` (PKCS#1 v1.5
  *encryption*, which SSH does not use), RSA-PSS/OAEP, SHA-224/SHA-3/SHAKE hash variants (no such SSH
  algorithms). Inside the converted files the tests skip only SHA-224 keys of `rsa_pkcs1_*_sig_gen` and expect
  compressed points to be rejected (SSH uses uncompressed points only).
- `rfc/rfc6979_ecdsa.txt`, `rfc/rfc5903_ecdh.txt`: RFC 6979 Appendix A.2.5-A.2.7 (P-256/384/521 keys and the
  "sample"/"test" signatures; SHA-224 left out) and RFC 5903 Section 8 (ECDH), extracted from the RFC texts by
  `refimpl/pk_ref.py`, which recomputes and asserts every extracted value with its own arithmetic first.
- `refimpl/bn_random.txt`, `ec_random.txt`, `rsa_keys.txt`, `dh_gex.txt`: produced by `refimpl/pk_ref.py`, our
  own deliberately simple Python big-integer reference (square-and-multiply, extended Euclid, affine curve
  formulas, RFC 6979 with Python's `hmac`/`hashlib`, RSA keys from its own Miller-Rabin; 01 Section 2.7.4),
  fixed seeds. `rsa_keys.txt` holds test-only RSA keys (1024 with e = 3, 1536 with p < q, 2048, 3072, 4095 with
  e = 17, 8192, 16384); they protect nothing. `dh_gex.txt` uses the RFC 3526 1536- and 3072-bit groups (safe
  primes outside sd_crypto's known-group table) and generated non-safe primes / composites. Regenerate with
  `python -I tests/vectors/refimpl/pk_ref.py <rfc5903.txt> <rfc6979.txt> <rfc3526.txt> tests/vectors`.
- Embedded in the test sources: FIPS 180-4 / NIST CSRC SHA-1 examples, RFC 2202 (HMAC-SHA1), RFC 6070
  (PBKDF2-HMAC-SHA1).
- Generated source data (not test data): `src/sd_crypto/pk_consts.inc` by `src/sd_crypto/gen_pk_consts.py` from
  the RFC 2409 / RFC 3526 MODP primes (cross-checked against their pi formula and tested as safe primes) and the
  RFC 5903 curve parameters (checked: primes, G on the curve, n*G = O).
